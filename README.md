# Car Marketplace AI Analyst

A Streamlit prototype for exploring vehicle-market CSV data through natural-language questions. It combines LLM-generated pandas analysis with retrieval-augmented generation (RAG), so responses can use relevant material from a local vehicle knowledge base.

## Features

- Upload CSV datasets through an interactive Streamlit interface.
- Inspect row counts, columns, missing values and numeric fields.
- Ask natural-language questions about summaries, trends, correlations and outliers.
- Generate Plotly visualisations where appropriate.
- Retrieve context from local text files using Sentence Transformers and FAISS.
- Produce concise, business-oriented explanations with a Groq-hosted language model.

## Workflow

1. Upload a CSV file.
2. Retrieve relevant paragraphs from the local knowledge base.
3. Send the question, dataframe schema and retrieved context to the LLM.
4. Generate pandas-oriented Python code.
5. Apply keyword-based checks, execute the generated code and display its result.
6. Generate a natural-language explanation.

## Technology

Python, Streamlit, Groq API (Llama 3.3 70B Versatile), Pandas, NumPy, Plotly, Sentence Transformers (`all-MiniLM-L6-v2`), FAISS, SciPy and python-dotenv.

## Run locally

Clone the repository and enter its directory:

```bash
git clone https://github.com/Bokang-code/GenAi_Hackathon_M00861576.git
cd GenAi_Hackathon_M00861576
python -m venv .venv
```

Activate the environment:

```bash
# macOS / Linux
source .venv/bin/activate

# Windows PowerShell
.venv\Scripts\Activate.ps1
```

Install dependencies:

```bash
pip install -r "DEMO PROJECT/requirements.txt"
```

Create a local `.env` file in the repository root:

```dotenv
GROQ_API_KEY=your_groq_api_key
```

Then launch the application:

```bash
streamlit run "DEMO PROJECT/app.py"
```

The first RAG initialisation may download the embedding model. Upload a CSV in the sidebar to start analysing it.

## Knowledge base and data

The application reads `.txt` files from `DEMO PROJECT/knowledge_base/`, splits their contents into paragraph-sized chunks and indexes the embeddings with FAISS. Add relevant, appropriately licensed reference material to enrich domain-specific responses.

Do not upload confidential or sensitive datasets to an external LLM service unless you have the necessary authorisation and safeguards.

## Security and limitations

**This is a hackathon prototype, not a secure production analytics service.**

- The current implementation executes Python code generated by an LLM using `exec`. Keyword filtering is not a security boundary and does not make arbitrary generated code safe. Do not expose this app to untrusted users or sensitive datasets in its current form.
- Generated analysis can be incorrect or misleading and should be validated.
- RAG currently uses simple paragraph chunking and retrieves only a small number of chunks.
- The app relies on an external Groq API and a locally downloaded embedding model.
- Authentication, tenant isolation, a hardened execution sandbox and comprehensive audit logging are not implemented.

For production use, replace unrestricted code execution with a constrained analytics interface or isolated sandbox; add authentication, access controls, allowlisted operations, tests and monitoring.

## Potential improvements
